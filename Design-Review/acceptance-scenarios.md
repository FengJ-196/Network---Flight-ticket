# Acceptance scenarios (Given / When / Then)

Requirement IDs: R1 socket connection (2 pts) · R2 server logging (1) · R3 register/login (2) · R4 search (2) · R5 compare (2) · R6 book + pay (3) · R7 e-ticket code (2) · R8 manage tickets (3) · R9 notifications (3). C1 = USER/ADMIN roles, C2 = balance payment.
"Ex #n" points to [wire-examples.md](wire-examples.md). Time-dependent cases use a fixed 2026-11-04 server clock (+07:00); use a fresh seed per independent scenario unless a case explicitly continues the transcript. All AS cases below are **planned**, not executed against an application. Source mapping: [README](README.md); procedures: [use-case-flows.md](use-case-flows.md).

| ID | Req | Scenario |
|---|---|---|
| AS-01 | R1 | **Given** server running **When** a client connects and sends `PING` **Then** `PING_RESP ok` and logs show CONNECT, RECV, SEND. Two clients can connect at once and get independent sessions. |
| AS-02 | R1 | **When** a client sends a non-JSON line **Then** `E_BAD_JSON` (`ERROR_RESP`, `id:null`), connection stays open, server keeps serving others (Ex #3–4). |
| AS-03 | R1 | **When** a UTF-8 JSON payload exceeds 65,536 bytes excluding LF/optional CR **Then** bounded buffering, `E_FRAME_TOO_LARGE` if possible and connection close; other clients unaffected. Exactly 65,536 payload bytes remain permitted if otherwise valid. |
| AS-04 | R2 | **When** any request/response/push/rejection occurs **Then** logs contain timestamp, conn, peer, user, type/id, original byte count, recursively redacted content and result. SEND_ATTEMPT is distinct from SEND_SUCCESS/FAILURE; passwords/contacts/passenger data never appear in clear. |
| AS-05 | R3 | **When** `REGISTER` valid **Then** user created with balance 5,000,000, role USER, not logged in (Ex #5–6). Duplicate username → `E_USERNAME_TAKEN` (Ex #7–8). Short password → `E_VALIDATION`. |
| AS-06 | R3 | **When** wrong password **Then** `E_BAD_CREDENTIALS`; unknown user gives the identical reply (Ex #9–10). Correct → role, balance, `unreadNotifications` (Ex #11–12). Second `LOGIN` on same connection → `E_ALREADY_LOGGED_IN`. |
| AS-07 | R3, C1 | **Given** no login **When** `SEARCH_FLIGHTS` **Then** `E_NOT_AUTHENTICATED` (Ex #1–2). **Given** USER **When** `ADMIN_UPDATE_FLIGHT` **Then** `E_FORBIDDEN`, flight unchanged (Ex #39–40). |
| AS-08 | R4 | **Given** seed data **When** HAN→SGN 2026-12-20, return 2026-12-27, 2 pax, ECONOMY **Then** outbound offers sorted by price (F1002, F1003, F1004, F1001), inbound (F2002, F2001), `totalPrice = 2 × pricePerPax` (Ex #15–16). |
| AS-09 | R4 | Edge: `passengers:0` → `E_VALIDATION field=passengers` (Ex #13–14); `returnDate` before `departDate` → `E_VALIDATION`; route with no flights → `ok` with empty arrays; flights with fewer free seats than passengers are omitted. |
| AS-10 | R5 | **When** compare F1001, F1002, F1003, ECONOMY, 2 pax **Then** cheapest = F1002, fastest = F1003, deltas +1,120,000 / 0 / +600,000 VND and 5 / 5 / 0 min (Ex #17–18). Mixed route/date or duplicate IDs → `E_VALIDATION`; unknown id → `E_NOT_FOUND`; unavailable → flight/seats error; 1 or 6 IDs → `E_VALIDATION`; ties use ascending flightId. |
| AS-11 | R6 | **When** `BOOK_FLIGHT` F1002+F2002, 2 pax **Then** `PENDING_PAYMENT`, total 5,280,000, hold 10 min, seats −2 on each flight (Ex #19–20). |
| AS-12 | R6, C2 | **Given** balance 5,000,000 and total 5,280,000 **When** `PAY_BOOKING` **Then** `E_INSUFFICIENT_BALANCE {required:5280000, available:5000000}`, balance and booking unchanged (Ex #21–22). |
| AS-13 | R6, C2 | **When** `BOOK_FLIGHT` F1003 1 pax (1,590,000) then `PAY_BOOKING` **Then** `TICKETED`, `balanceAfter = 3,410,000` and `GET_BALANCE` agrees (Ex #23–26). Repeating `PAY_BOOKING` with the same key returns the same reply and does not debit twice; a new key → `E_STATE_CONFLICT`. |
| AS-14 | R6 | **Given** a pending booking **When** 10 min pass **Then** status `EXPIRED`, seats restored, `PAY_BOOKING` → `E_HOLD_EXPIRED`. Two users racing for the last seat: exactly one gets it, the other `E_SEATS_UNAVAILABLE`. |
| AS-15 | R7 | **Given** a configured real email provider/sender and controlled recipient mailbox **When** payment commits **Then** PAY returns eTicketCode, one ticketNo per passenger and delivery.email.status QUEUED with one durable email job (Ex #26). Worker sends actual email; GET_BOOKING later reports SENT on provider acceptance. Verify the email arrives in the recipient inbox with the matching booking/ticket codes and itinerary. Provider acceptance or a local log alone does not pass receipt verification. |
| AS-16 | R7 | **When** RESEND_TICKET with bookingCode queues a real email **Then** channel EMAIL, masked booking contact email and QUEUED/SENT/FAILED status (Ex #27–28); confirm actual inbox receipt with the same ticket codes and no extra charge/ticket issue. Unpaid/cancelled booking → E_STATE_CONFLICT. Destination/channel overrides and obsolete phone fields → E_VALIDATION. Provider error may set FAILED while the booking stays TICKETED. |
| AS-17 | R8 | **When** `LIST_BOOKINGS` **Then** both Alice's bookings newest first (Ex #29–30); `GET_BOOKING X4K9PL` shows legs, tickets, paid amount (Ex #31–32); another user's code → `E_NOT_FOUND`. |
| AS-18 | R8 | **When** `PRINT_TICKET` **Then** `lines[]` containing PNR, passenger, ticket no, flight, times, class; client saves/prints `ticket-X4K9PL.txt` (Ex #33–34). Pending booking → `E_STATE_CONFLICT`. |
| AS-19 | R8 | **When** change leg to F1004 (dry-run quote then apply with quoteId/key) **Then** fee 200,000 + difference 160,000 = 360,000, balance 3,410,000 → 3,050,000, identifiers unchanged, revision increments, seats swapped; dry run holds no seats and changes no money/booking (Ex #35–38). Route mismatch/any old or new departure <2h → `E_CHANGE_NOT_ALLOWED`; low balance → `E_INSUFFICIENT_BALANCE`. Equal/cheaper changes settle signed net correctly and failed replacement preserves original tickets/itinerary. |
| AS-20 | R8 | **Given** a non-disrupted paid booking **When** cancelling ≥2 h before its earliest departure (including exactly 2 h) with bookingCode/key and no quote **Then** fee 0, refund 100% of fare (1,750,000 → 1,750,000), all-leg seats released. <2 h → E_CANCEL_NOT_ALLOWED. Same-key retry replays without another refund; new-key cancellation or preview on a terminal booking → E_STATE_CONFLICT. A live PENDING_PAYMENT cancellation releases all holds, refunds zero and leaves balance unchanged. Optional preview neither stores a quote nor binds the later apply. |
| AS-21 | R9, C1 | **Given** Alice online with a TICKETED booking on F1004 **When** admin DELAY 150 min with expectedVersion/key **Then** flight version and booking revision increment; counts say 1 affected and 1 connection queued; Alice receives NOTIFY DELAY with new times/flightVersion/freeCancellation:true (Ex #43–45). Count does not prove successful write/read. |
| AS-22 | R9 | **Given** Alice offline **When** admin updates flight **Then** notification persists; at next LOGIN unreadNotifications ≥1; GET_NOTIFICATIONS returns full notification; ACK_NOTIFICATION marks read. Ex #46–49 illustrate online pull/ack only, not executed offline recovery. Acking another user's ID → `E_NOT_FOUND`. |
| AS-23 | R9, R8 | **Given** disrupted booking before departure, including <2 h away, **When** `CANCEL_BOOKING` without a quote **Then** fee 0, refund = fare 1,750,000 (change fee excluded), balance 3,050,000 → 4,800,000 (Ex #50–53). |
| AS-24 | R9 | **When** admin CANCEL commits **Then** each affected live TICKETED booking becomes FLIGHT_CANCELLED, outstanding net paid refunded, NOTIFY FLIGHT_CANCELLED includes refundAmount, and flight leaves search. Same-key retry replays without another refund; a distinct new-key update on that cancelled flight → E_STATE_CONFLICT. |
| AS-25 | R9 | **Given** a fresh ticketed seed flight **When** DELAY lacks delayMinutes or RESCHEDULE has arrive≤depart/action-incompatible fields **Then** E_VALIDATION and no update. A net 60-minute delay gives freeCancellation:false; absolute net shift ≥120 minutes in either direction gives true. Corrections use accepted baseline rather than sum of absolute edits. |
| AS-26 | R1, R6 | **Given** client sent `PAY_BOOKING` and lost the connection **When** it reconnects, logs in, and resends with the same `idempotencyKey` **Then** one debit only and identical result. |
| AS-27 | R1 | **Given** an encoded Unicode frame and two consecutive frames **When** a harness splits at every byte (including within a multibyte character), coalesces frames, uses CRLF or forces short writes **Then** identical complete messages are dispatched once, with no interleaved push/reply bytes. EOF mid-frame or ten-second frame deadline discards unfinished data and closes without handler side effects. |
| AS-28 | R6, R9 | **Given** a pending round trip **When** admin DELAY/RESCHEDULE touches either leg **Then** whole pending booking becomes CANCELLED reason FLIGHT_UPDATED, all-leg holds release, no debit, later PAY → E_FLIGHT_UNAVAILABLE. Race with PAY must yield invalidated unpaid hold or successful payment followed by persisted flight notification. |
| AS-29 | R6, R9 | **Given** ticketed round trip including prior change fees **When** admin cancels either leg while payment/change/cancel contends **Then** one serial outcome, all affected live legs released, no active ticket on cancelled flight, at most one outstanding-net-paid refund, no negative inventory/balance and no repeated refund for terminal bookings. |
| AS-30 | R8 | **Given** a 60-second change quote **When** now reaches expiry, booking/flight version changes, another operation consumes it or the quoted change amount changes **Then** E_QUOTE_EXPIRED or E_VERSION_CONFLICT; no silent repricing/debit. An owned-quote parameter mismatch → E_VALIDATION; another owner's quote → E_NOT_FOUND. Client obtains a new quote and acceptance. |
| AS-31 | R6, R8, R9 | **Given** applied BOOK/PAY/CANCEL/CHANGE/ADMIN_UPDATE committed but reply was lost **When** same user retries identical payload/key (new request ID, including after restart/quote expiry/terminal booking) **Then** saved outcome replays without another seat swap/debit/refund/delay/push. Same key/different payload → E_IDEMPOTENCY_CONFLICT; a new key is a distinct operation and must pass current guards. |
| AS-32 | R9 | **Given** several sockets for one user and duplicated/out-of-order NOTIFY **When** client receives them **Then** deduplicate notificationId and refresh authoritative booking. Full push/list fields agree. An ACK batch containing any missing/foreign ID marks none; repeated all-owned ACK succeeds with distinct supplied count. |
| AS-33 | R3, R8, R9 | **Given** separate customer/admin sockets **When** one user supplies another's booking/quote/notification ID, a role/userId extra field, or a customer admin action **Then** ownership/privacy/strict-payload checks reject it; stored session identity alone controls authority. Disconnecting one socket does not authenticate a new connection or affect another socket's login. |
| AS-34 | R4, R8, R9 | **Given** empty, multi-page and terminal fixtures **When** lists use limit/offset/filter **Then** bounded frames, documented stable sorting, nextOffset/null and own-data filtering. Client deduplicates/restarts pages after concurrent mutations. Cancelled/expired bookings remain viewable; print/resend reject terminal tickets; no unbounded result allocation. |
| AS-35 | R6, R7, R9 | **Given** provider outage/timeout or crash after SQL commit and before reply/push/email status persistence **When** recovery runs **Then** payment/key/tickets survive; overdue holds expire once; durable email jobs resume with bounded retries and safe attempt diagnostics; FAILED never reverses payment; missed push remains retrievable. Recheck booking/revision before sending. An uncertain provider acceptance can duplicate email on retry, never charge/tickets; demonstrate that case without claiming exactly-once mail receipt. |
| AS-36 | R2 | **When** malformed input contains a password/contact or a socket write fails midway **Then** logs expose only safe invalid-input metadata, record SEND_FAILURE rather than completion, recursively redact nested personal data and printable lines, and retain correlation metadata for rejected requests and pushes. |
| AS-37 | R4, R6, R8 | **When** hold/quote expiry equals now, departures hit exact 2h/0h boundaries, DOB crosses age 18 or a return precedes outbound arrival **Then** inclusive/exclusive policies match business-flow.md in +07:00. Disruption never allows post-departure cancel/change. No cancellation percentage/tier calculation exists; eligible paid cancellations refund the full fare. |
| AS-38 | R1, R3 | **When** complete frames contain invalid UTF-8/JSON, duplicate keys, boolean version, non-object data, duplicate request ID, wrong-direction type or unknown fields **Then** correct ERROR_RESP/typed rejection and no business effect; safe complete-line errors keep the connection open. Idle receive timeout is 300s; outgoing pushes cannot extend it. |
| AS-39 | R1, R9 | **Given** the built server on PC A and client on physically separate PC B **When** using PC A's reachable LAN address and matching FBP version **Then** PING/login/purchase work and admin-triggered push/offline recovery works, with redacted evidence from both PCs. Localhost success alone does not pass. Setup follows application-design.md. |
| AS-40 | R4, R6 | **Given** fresh seed balance 5,000,000 **When** one adult books/pays F1002+F2002 ECONOMY **Then** total 2,640,000, balance 2,360,000 and exactly one seat sold per leg; no partial round trip. PREMIUM_ECONOMY/BUSINESS searches use the additional F1001/F2001 fixtures, independent capacities and correct per-passenger totals. |

Evidence for completion at the implementation milestone: record executed AS-01–40 results, fixture/time setup, SQL/inventory/ledger assertions, redacted log excerpts, actual e-ticket emails in a controlled recipient mailbox, provider failure/retry results and two-PC traces.
