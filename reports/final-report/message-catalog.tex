\begin{frame}{Booking lifecycle and system responsibilities}
\small\contractrows
\begin{tabularx}{\textwidth}{@{}p{2.65cm}Y@{}}
\labelrow{Customer} & Search and compare offers, then confirm the itinerary and total fare. One booking request purchases the tickets using the signed-in customer's stored balance. \\
\addlinespace[2pt]
\labelrow{Server} & The server binds the signed-in role to the connection and logs requests and replies with sensitive fields redacted. The server owns inventory, booking revisions and balances. One database transaction sells the seats, debits the account, issues the tickets and queues the email for delivery after commit. \\
\addlinespace[2pt]
\labelrow{Administrator} & A delay, reschedule or cancellation updates affected bookings. The server stores customer notifications and also pushes them to online clients. \\
\end{tabularx}

\end{frame}

\begin{frame}{How to read a message contract}
\small\contractrows
\begin{tabularx}{\textwidth}{@{}p{2.65cm}Y@{}}
\labelrow{Request} & One UTF-8 JSON object per line over TCP. Required envelope fields are \msg{v} (integer 1), \msg{type} (uppercase command), \msg{id} (unique on this connection) and \msg{data} (object). \\
\addlinespace[2pt]
\labelrow{Reply} & Append \msg{_RESP} to the command and echo its ID. Success adds \msg{ok} = true and \msg{code} = OK. Failure sets \msg{ok} = false and supplies a stable error code, a human-readable \msg{message} and structured context in \msg{data}. \\
\addlinespace[2pt]
\labelrow{Push} & \msg{NOTIFY} uses a null ID. A push may arrive before a pending reply. Match replies by ID and dispatch pushes by type. \\
\addlinespace[2pt]
\labelrow{Field notation} & The following contracts list the fields inside \msg{data}. Fields marked ? are optional or conditional. An empty object is written \{\}. The example on the next slide omits the constant version field for readability. \\
\end{tabularx}

\end{frame}

\begin{frame}{Which error does the server return?}
\small\contractrows
\begin{tabularx}{\textwidth}{@{}p{2.65cm}Y@{}}
\labelrow{1. Decode} & Check frame size, UTF-8 and JSON, then envelope, version, direction, command and request ID. Send \msg{ERROR_RESP} for failures at this stage. Echo a usable ID when available. Malformed JSON and oversize frames use null. \\
\addlinespace[2pt]
\labelrow{2. Authorize} & For a recognized request with a valid envelope, use its typed reply. Check login for protected commands and role where restricted. Then validate payload fields. Report the first invalid required field, then optional or conditional fields in catalog order. \\
\addlinespace[2pt]
\labelrow{3. Check retry} & For requests with an idempotency key, look up (user, type, key). An exact replay returns the saved success. A changed payload with the same key produces \msg{E_IDEMPOTENCY_CONFLICT}. \\
\addlinespace[2pt]
\labelrow{4. Apply} & Run the checks required by the command. A purchase checks seats and funds. An inbox read checks ownership. A failure after commit requires recovery of the saved result or connection closure so the client can reconcile. \\
\end{tabularx}

\end{frame}

\begin{frame}{Appendix: shared field types}
\small\contractrows
\begin{tabularx}{\textwidth}{@{}p{2.65cm}Y@{}}
\labelrow{Identifiers} & Resource IDs are nonempty ASCII strings up to 64 characters. Booking and e-ticket codes are six uppercase letters or digits. A request ID or mutation key is 1--64 ASCII letters, digits, underscores or hyphens. \\
\addlinespace[2pt]
\labelrow{Dates and money} & Dates use YYYY-MM-DD. Timestamps include the +07:00 offset. Amounts are integer VND. Fare differences, net change amounts and projected balances may be signed. Versions and revisions start at 1. \\
\addlinespace[2pt]
\labelrow{Seat and leg} & Seat class is ECONOMY, PREMIUM\_ECONOMY or BUSINESS. A leg is OUTBOUND or RETURN. Airport codes are three uppercase letters. \\
\addlinespace[2pt]
\labelrow{Pagination} & \msg{limit} is 1--20 (default 20). \msg{offset} is 0--10000 (default 0). \msg{nextOffset} is the next integer offset, or null at the end. Optional boolean flags default to false. \\
\end{tabularx}

\end{frame}

\begin{frame}{Frame and envelope errors}
\footnotesize\renewcommand{\arraystretch}{1.06}
\begin{tabularx}{\textwidth}{@{}lYY@{}}
\toprule \labelrow{Code} & \labelrow{Trigger and error data} & \labelrow{Client action} \\
\midrule
\msg{E_BAD_JSON} & Invalid UTF-8 or JSON object, duplicate keys or malformed complete line. Empty context. & Fix the encoding and send a new frame. The connection stays open. \\
\addlinespace[1pt]
\msg{E_FRAME_TOO_LARGE} & Payload exceeds 65,536 bytes before the delimiter. Context gives \msg{maxBytes}. & The server replies if possible and closes. Reduce the payload and reconnect. \\
\addlinespace[1pt]
\msg{E_UNSUPPORTED_VERSION} & Unsupported integer version. \msg{supported} contains [1]. & Select a supported version. \\
\addlinespace[1pt]
\msg{E_UNKNOWN_TYPE} & Unknown command. Context echoes \msg{type}. & Correct the request type. \\
\addlinespace[1pt]
\msg{E_VALIDATION} & Invalid envelope, field or combination. Context gives \msg{field} and \msg{reason}. & Correct the indicated field. An invalid envelope uses \msg{ERROR_RESP}. \\
\bottomrule
\end{tabularx}
\end{frame}
